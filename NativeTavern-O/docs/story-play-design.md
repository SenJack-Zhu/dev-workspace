# 故事玩法设计

日期：2026-08-23

## 目标

故事不再只是对话摘要。它把已经发生的聊天整理成可操作的故事节点，
让用户可以沿着未决线索继续、从一个节点保留式分叉，并比较不同路线
后来发生了什么。

最小玩法循环：

```text
经历一段对话 -> 形成故事节点 -> 继续或分叉 -> 产生不同后果 -> 对照路线
```

## 章节节点

每章保留原有标题、摘要、消息范围和来源跳转，并新增四类结构化内容：

- 关键事件：这一章实际发生了什么。
- 状态变化：关系、承诺、地点、目标或公开事实发生了什么变化。
- 未决线索：已经提出但尚未解决的冲突、问题或承诺。
- 下一步：可以自然接着演的方向。它们是草稿，不是强制选项。

旧章节没有结构化内容时仍可正常显示，以摘要作为关键事件。

## 接着演

用户从章节选择一个未决线索或下一步，回到原聊天。输入框预填一条可编辑
草稿；只有用户发送后才进入世界。系统不替用户自动发送，也不偷偷推进。

## 保留式分叉

现有书签分支会删除检查点后的消息，适合回滚，不适合比较结局。故事分叉
采用复制会话：

1. 复制源聊天到所选章节的结束消息。
2. 复制此前所有章节，并重新绑定新消息 ID。
3. 在新聊天设置中记录根路线、父路线、分叉章节和分叉序号。
4. 原聊天保持不变；新聊天从相同历史继续。

分叉失败时删除未完成的新聊天，不留下半成品。

分叉后的自动长期记忆按聊天路线写入。生成上下文可以读取当前路线和祖先
路线在分叉点之前的记忆，但不会读取兄弟路线，或祖先路线在分叉点之后才
发生的事实。未分叉聊天仍使用原有的角色/人设共享记忆。

## 后果对照

同一根路线下至少有两条聊天时可以对照。共同历史不重复展示，只比较各自
分叉点之后的章节摘要、状态变化和仍未解决的线索。没有新章节时明确显示
“尚未形成后果”，不让模型补写不存在的结果。

## 数据契约

章节的结构化内容存放在 `story_chapters.narrative_json`。分支图复用
`chats.settings_json`，键名如下：

- `storyRootChatId`
- `storyParentChatId`
- `storyForkChapterId`
- `storyForkOrdinal`
- `storyBranchTitle`

没有这些键的历史聊天就是自己的根路线，完全向后兼容。

## 非目标

- 不自动替用户选择下一步。
- 不用好感度、经验、稀有度包装章节。
- 不把动态帖当作章节，也不从章节自动灌动态。
- 本版不复制独立 RPG 快照；普通聊天和群聊的消息、章节与聊天设置会复制。
