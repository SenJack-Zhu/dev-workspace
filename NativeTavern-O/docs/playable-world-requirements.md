## 1. 目标

### 1.1 要解决的问题

现有产品能力已经接近 ST 移动端，但对新手是「设置很多，世界感很少」。商业陪伴 App 用抽卡和好感度制造进度，我们不走这条路。单机要挖的是：

1. 长线关系会留下能回看的故事，而不只是消息泡。
2. 规则状态是真的，模型不能嘴炮改血量和背包。
3. 群聊能当戏导，书签能当平行世界。
4. 用户自己的小说/设定能当战役圣经。
5. 以上全部有合理默认。想调的人可以一直往下挖。

### 1.2 成功标准

- 新用户：配好模型后，打开角色就能聊。不需要理解记忆、场景、导演、资料库。
- 7 天用户：聊天里能看到自动生成的章节/高光，点开就懂「原来故事在积累」。
- 深度用户：能导入场景包、改规则、导戏、挂资料、走分支树，上限不低于桌面 ST + 本地跑团。
- 任何新能力都可以一键关掉，关掉后提示词和现网聊天行为一致。

### 1.3 非目标

- 不做社交、交易、抽卡、体力、每日登录。
- 不做角色工坊市场、扩展商店、玩法包商店。
- 不做内置本地 LLM / Embedding / TTS / STT 模型下载管理。
- 不把 NativeTavern 做成通用 Agent 工作台。MCP 只作为可选进阶。
- 不和 ChatGPT 比「更会当朋友」。护城河是存档、规则、世界和导演权。

## 2. 产品原则：低地板、高天花板

所有新需求必须同时写清 **默认路径** 和 **进阶路径**。缺一不可。

### P1. 默认即完整体验

用户什么都不开，也能完成「选角色 → 聊天 → 回看 → 分支」。默认机制必须自己工作，不能靠用户先填 20 个框。

### P2. 概念最多一次出现一个

同一屏幕不要同时教记忆、场景、导演、资料库。新概念只在用户第一次真正用到时出现，并且可以跳过。

### P3. 三层信息，不把工坊摊到聊天上

| 层 | 给谁 | 里面有什么 | 默认 |
| --- | --- | --- | --- |
| 聊天 | 所有人 | 发消息、swipe、语音、立绘 | 打开即用 |
| 故事 | 聊过一段时间的人 | 章节、时间线、高光、角色记得的事 | 有内容才显示入口 |
| 玩法 | 想玩规则/群像/资料的人 | 场景、导演、资料、动态、世界日更、桌上玩具 | 入口在「玩法」，默认关闭 |
| 工坊 | 作者/ST 老用户 | 场景编辑器、世界书、正则、预设、提示词 | 维持现有深层设置，不前移 |

### P4. 静默优于打断

自动提取、自动分章、自动建议行动，默认不弹窗。需要确认时进收件箱或小红点，绝不挡输入框。

### P5. 关掉必须干净

每个玩法有总开关。关闭后：不注入上下文、不写新数据（或只写可清理的草稿）、不改现有聊天手势。

### P6. 复用现有底盘，不另起炉灶

记忆、RPG 契约、资料库、书签、群聊、Live2D/语音已经有代码和路线。本需求是给它们补上「产品默认」和「叙事层」，不是重做引擎。

## 3. 玩法入口与默认界面

底栏：聊天 | 角色 | **玩法** | AI | 设置。  
「玩法」替换「世界书」。

### 3.1 两层点击，不要一页塞完

1. 点底栏「玩法」→ 只出现二级菜单：动态、故事、场景、世界书、资料。
2. 再点其中一行 → 才进入该系统。

玩法页不是仪表盘。就是这五行菜单。

### 3.2 四个系统进去以后是什么

| 菜单 | 从哪来 | 进去后的首页 | 塞进这个系统内部、不上菜单 |
| --- | --- | --- | --- |
| 动态 | 新 | 帖的时间线 | 可见范围、写入世界 |
| 故事 | 新 | 章节时间线 | 记忆收件箱、故事树、世界日更 |
| 场景 | 已有 RPG 引擎 + 新第一夜 | 正在玩，或开始第一夜 | 场景编辑器、骰子、命运时钟 |
| 世界书 | 已有，现底栏 | 独立的世界书库（现在那一页） | 条目编辑仍在书里，不上玩法菜单 |
| 资料 | 已有资料库，现设置里 | 独立的文档库 | 切块/Embedding 在库内部 |

编辑器、导入、参数放在各系统内部，不回到玩法菜单上。

### 3.3 和聊天、设置

聊天页继续只聊天。顶栏不堆这四个入口。  
设置里的界面详细程度保留。设置若还留记忆/场景/资料，只跳到对应系统，不当首页。

### 3.4 验收

- 底栏第三项是玩法。点一下只到四行菜单。
- 进故事必须再点「故事」。玩法页上看不到章节正文。
- 四个系统首页都是在用的内容或明确空态，不是设置表单。
- 世界书编辑器不能从底栏一步直达，只能菜单 → 世界书 → 系统内再编辑。

## 4. P0 需求包：故事层

把已有长期记忆从「检索插件」做成「能读的故事」。这是单机版对标星念的诚实做法：物证只属于用户，没有抽卡。

现有底盘：`long_term_memory`、记忆收件箱、上下文注入、书签。

### 4.1 默认路径（新手）

1. 用户照常聊天。
2. 后台在合适节奏提取记忆（复用当前聊天 LLM；无 LLM 则只支持手动）。
3. 高置信条目静默写入；低置信进收件箱，不打断。
4. 大约每 20 条用户+角色来回，或用户手动点「记一笔」，生成一章短摘要。
5. 顶栏出现「故事」。点进去能按时间看章节，点章节能跳回原消息。
6. 用户可以完全不点「故事」，聊天不受影响。

### 4.2 进阶路径（天花板）

- 记忆柜：按人物、关系、承诺、偏好、未决事项筛选。
- 每条记忆可编辑、合并、锁定、作废、跳转来源。
- 「它记得什么」：以角色口吻只读预览当前会注入的记忆。
- 高光：把一段消息收成卡片（标题、摘句、可选立绘），留在故事里。
- 导出：章节 + 高光导出 Markdown。
- 分支隔离：从书签长出的平行世界，故事对象不串味。
- 可选 Embedding 重排；失败自动退回 FTS。

### 4.3 功能需求

| ID | 级别 | 需求 |
| --- | --- | --- |
| ST-01 | Must | 故事对象类型：章节、高光、记忆条目。绑定到聊天/群聊/角色作用域。 |
| ST-02 | Must | 默认自动分章。阈值可调，默认 20 轮。用户可「提前结章」。 |
| ST-03 | Must | 章节含标题、摘要、起止消息、时间。点章节滚动到原位置。 |
| ST-04 | Must | 记忆高置信静默写入，低置信进现有收件箱。阈值有默认，可调。 |
| ST-05 | Must | 故事页默认只显示章节时间线。记忆柜、收件箱放二级入口。 |
| ST-06 | Must | 注入预算和「本次用了哪些记忆」沿用现有面板，默认折叠。 |
| ST-07 | Must | 关闭「故事与记忆」后不再提取、不再注入；已有数据保留可清理。 |
| ST-08 | Should | 一键收藏高光，自动带附近摘句。 |
| ST-09 | Should | 导出 Markdown。 |
| ST-10 | Should | 群聊按角色过滤「谁记得什么」。 |
| ST-11 | Later | 把高光渲染成立绘明信片。不阻塞第一期。 |

### 4.4 非目标

- 不做稀有度、交易、分成。
- 不把收件箱做成每次回复后的强制审核流。
- 第一期不做视频/语音故事回顾。

### 4.5 验收

- 连续聊 30 轮后，不打开任何设置，故事页至少有 1 个章节。
- 关掉功能后，同样预设的请求不再包含记忆块。
- 从书签回滚再开新支，旧支章节不出现在新支时间线。
- 无 LLM 时仍可手动写记忆、建章节、全文检索。

## 5. P0 需求包：RPG 开箱能玩

现有底盘：`RpgScenario` 契约、规则引擎、叙事桥接、状态面板、场景编辑器。缺的是「不进编辑器也能玩」。

### 5.1 默认路径（新手）

1. 普通聊天默认不是 RPG。
2. 会话菜单「玩法 → 场景」打开后，先看到 1 个官方入门包「第一夜」，一句话：「今晚刚住下，说话和行动都会留下后果。」
3. 一点「开始」，当前聊天绑定该场景。聊天页侧面/底部出现极简状态条：体力、金币、好感、地点。
4. 模型只负责演。改血、扣钱、接任务必须经规则引擎。非法叙事补丁被拒绝，用户无感（不弹技术错误），状态不变。
5. 用户仍用自然语言玩。需要时出现 2–4 个建议行动，可忽略。
6. 不打开场景编辑器也能完整玩完入门包。

### 5.2 进阶路径（天花板）

- 导入 JSON/YAML 场景包，校验失败给可读错误。
- 现有场景编辑器继续服务作者：属性、物品、地点、任务、行动、保护字段。
- 存档快照、回滚、分支继承。
- 同一种子 + 同一输入可复现。
- 自定义保护字段，防止模型改库存/任务/随机源。
- 场景与故事层打通：重大规则事件自动记一章（任务完成、角色死亡、地点转移）。

### 5.3 官方入门包「第一夜」

必须随应用内置，体积小，不依赖外部资源。产品名里的 tavern 是角色聚集地，入门包不要做成酒吧或喝酒。

- 地点：门厅、客房、后院。
- 属性：体力、零钱。关系：房东信任。
- 物品：旧钥匙（后期）。
- 任务：安顿下来 / 打听那扇锁着的门。
- 行动：休息、付房钱、提问、出门、去锁门房间（需钥匙或足够信任）。
- 骰子：仅在规则需要时掷，默认 `2d6`，结果写进回合日志，不强迫用户懂规则术语。

这是默认教学，不是唯一玩法。用户可随时卸载绑定，聊天回到普通模式。

### 5.4 功能需求

| ID | 级别 | 需求 |
| --- | --- | --- |
| RPG-01 | Must | 普通聊天零 RPG UI。未绑定场景时规则引擎不运行。 |
| RPG-02 | Must | 内置「第一夜」，无需导入即可开始。 |
| RPG-03 | Must | 极简状态条默认只显示 3–4 个主状态；背包/任务/日志进「详情」。 |
| RPG-04 | Must | 叙事补丁必须走 `RpgScenarioValidator.validatePatch`。保护字段被拒。 |
| RPG-05 | Must | 建议行动可点可忽略。纯自然语言也应能触发已定义行动。 |
| RPG-06 | Must | 解除绑定不删除聊天记录；可选择保留或丢弃场景状态。 |
| RPG-07 | Must | 编辑器不出现在默认聊天路径。从玩法页「制作场景」进入。 |
| RPG-08 | Should | 规则大事件写入故事章节。 |
| RPG-09 | Should | 存档列表用人话命名：「安顿下来之后」「进了后院」。 |
| RPG-10 | Later | 可视化场景编辑器继续按 C07 做，但不作为开玩前置。 |

### 5.5 非目标

- 第一期不做战斗数值网、地图网格、多人本。
- 不做付费 scrim、体力。
- 不让 LLM 直接写 `RpgRuntimeState`。

### 5.6 验收

- 没碰过 RPG 的用户，主路径零场景术语。
- 用入门包玩 15 分钟，能看到状态变化和至少 1 个任务推进，且全程不用打开编辑器。
- 让模型在对话里宣称「你有 999 金币」后，状态条金币不变。
- 相同种子重放入门包关键选择，状态一致。

## 6. P1 需求包：导演台

现有底盘：群聊、5 种发言模式、静音、触发词。

### 6.1 默认路径

- 单聊不受影响。
- 群聊默认仍是现在的轮流/随机/全员/手动/自然。
- 群聊顶栏多一个「舞台」开关，默认关。
- 打开后只多两样：在场名单、下一口指定。足够把群聊当小剧场。

### 6.2 进阶路径

- 三轨：对白 / 内心 / 旁白。内心默认只有当事人和用户可见。
- 听力范围：不在场角色收不到该轮对白。
- 冻结、召回、让两人私下吵。
- 关系图只读预览（可和 RPG 关系分或记忆关系打通）。
- 舞台提示：地点、时间、气氛，作为一条系统注入，用户一句话就能改。

### 6.3 功能需求

| ID | 级别 | 需求 |
| --- | --- | --- |
| DR-01 | Must | 「舞台」默认关。关闭后群聊行为与现网一致。 |
| DR-02 | Must | 开启后可勾选在场角色、指定下一口。 |
| DR-03 | Must | 不在场角色不发言，也不把该轮对白写入其短期可见上下文。 |
| DR-04 | Should | 对白/内心/旁白标记。内心不泄漏给其他角色。 |
| DR-05 | Should | 一句话舞台提示（「灯暗下来，改到雨巷」）写入本轮上下文。 |
| DR-06 | Later | 可视化关系图、分镜时间轴。 |

### 6.4 验收

- 三人群聊：叫 A 回避后，A 的下一轮不能引用刚才 B、C 的私聊内容。
- 关闭舞台后，旧群聊模式全部回归。
- 单聊设置页不出现导演术语。

## 7. P1 需求包：故事树

现有底盘：书签、从检查点继续、回滚提示。

### 7.1 默认路径

- 书签交互保持：长按消息或 `/bookmark`。
- 用户不打开故事树就感觉不到新概念。
- 自动章节可以作为树的主干节点，但不强迫用户管理树。

### 7.2 进阶路径

- 「故事」里第二页是树：每个书签/分章是节点，分叉是「如果当时没那样说」。
- 从任意节点长出平行世界。记忆、章节、RPG 状态按支隔离。
- 两支结局可并排看摘要，不并排看全部气泡。
- 节点用人话标题，默认取章节名或书签名。

### 7.3 功能需求

| ID | 级别 | 需求 |
| --- | --- | --- |
| TR-01 | Must | 书签现有流程不回归。 |
| TR-02 | Must | 树视图是故事页的二级页，不是聊天默认 UI。 |
| TR-03 | Must | 分叉时复制必要状态（记忆作用域、RPG 快照），之后隔离写入。 |
| TR-04 | Should | 并排对比两支的章节摘要。 |
| TR-05 | Should | 导出一棵树的目录型 Markdown。 |
| TR-06 | Later | 把树画成可拖拽的大地图。 |

### 7.4 验收

- 从同一书签开两支，A 支表白、B 支离开，记忆柜互不出现对方关键事实。
- 未创建书签的用户，聊天页零「故事树」字样。

## 8. P1 需求包：战役圣经（资料库产品化）

现有底盘：Data Bank 屏幕、本地解析/FTS 路线。

### 8.1 默认路径

- 资料库不出现在聊天主路径。
- 玩法页「资料」：选文件 → 绑定到当前角色或当前聊天 → 完成。
- 默认用本地 FTS。不配 Embedding 也能用。
- 角色只会在相关时引用，回复里可展开「出处」，定位到章节/页码。

### 8.2 进阶路径

- 全局 / 角色 / 聊天三级绑定。
- 可见性：某角色只能知道某几章。
- PDF/EPUB、切块策略、token 预算、可选语义重排。
- 同一套资料挂多个存档。

### 8.3 功能需求

| ID | 级别 | 需求 |
| --- | --- | --- |
| DB-01 | Must | 默认关闭。未绑定则不注入。 |

## 10. P1 需求包：动态

对外就叫「动态」。这不是信息流，是第二舞台。

- 聊天 = 私下。当时发生了什么，故事页记账。
- 动态 = 公开。角色选择让别人看见什么。
- 玩点是缝：演、瞒、互撕、拆穿、装没看见。

默认关。打开后新手只看到时间线 + 评论 / 开聊 / 拆穿。谁能看见、写不写进世界，进「更多」。

### 10.1 为什么值得做成深度玩法

只转发章节摘要，动态是废的。深度来自四件事：

1. **说法和事实可以打架。** 角色发「昨晚没事」，章节里是吵过。用户能看实情，也能当众拆穿。
2. **发帖是行动，不是日报。** 显摆、试探、隐瞒、点名才发。没动机就空着。
3. **一条帖能把人拉回戏里。** 「开聊」带着帖进对话；忽略本身也记一笔。
4. **群像不用开群聊。** 角色按自己知道的评；不知情的人只能评帖面。

和已有包的边界：

| 已有 | 动态多出来的玩法 |
| --- | --- |
| 故事章节 | 章节是底账；动态是公开演出 |
| 高光 | 高光是你收藏；动态是角色主动抛出来的球 |
| 世界日更 | 日更是「你不在时发生了什么」；动态是各人怎么对外说 |
| 导演台 | 导演管这一场谁在场；动态管事后谁看得见、谁敢评、谁被拆穿 |

同一件事实只生成一次。动态换的是视角和社交后果，不另写一套剧情。

### 10.2 默认路径（新手）

1. 默认关。聊天页无入口、无红点、无推送、不后台刷帖。
2. 玩法里打开「动态」，会话菜单出现「动态」。不抢「故事」顶栏。
3. 时间线倒序。一张帖：谁发的、一句人话、可选图。
4. 帖下只有三个动作：评论、开聊、拆穿。
5. 有章节或第一夜大事件才派生帖。没新事就空着，空态说明原因。
6. 用户可以自己发一条。默认本场角色看得见。

### 10.3 进阶路径（天花板）

- **实情：** 有来源的帖可看故事里的版本，和公开说法对照。
- **拆穿：** 把已知事实甩到公开场。角色必须接住，不能装无事。拆穿结果可记进章节。
- **开聊：** 带着该帖和某个角色私下谈。角色知道你指哪一条。
- **已读不回：** 过一段时间没评、没开聊，可记「你没理」。再见面能被提起。不弹窗催。
- **互评与知情范围：** 只评自己知道的。导演台回避过的私场，评论里带不出来。
- **可见范围：** 公开 / 仅用户 / 点名某些人 / 排除某人。角色对某些人撒谎时用这个。
- **写入世界：** 用户发帖可勾选。勾了，后续聊天和规则都认；没勾就只是说说。
- **等待帖：** 角色点名问你一件事，状态是等你。你评、开聊或一直不理，三条路都算数。
- **RPG：** 帖可以挂已发生的规则事件，不能靠帖文改保护字段。
- **补生成：** 打开动态时每角色每世界日最多 0–1 条，有预算。失败只显示已有派生帖。
- **分支：** 平行世界的动态互不串。

### 10.4 功能需求

| ID | 级别 | 需求 |
| --- | --- | --- |
| DY-01 | Must | 默认关。关闭后无入口、无红点、无推送、不后台生成。 |
| DY-02 | Must | 帖子有作者、公开正文、时间、来源（章节 / 日更 / RPG / 用户）。 |
| DY-03 | Must | 公开说法允许和来源事实不一致。有来源的帖能看实情。 |
| DY-04 | Must | 无新事实不灌水。禁止天气、心情填空。 |
| DY-05 | Must | 评论、开聊。开聊把帖作为上下文带进对话。 |
| DY-06 | Must | 拆穿：把已知事实对上公开说法，角色必须回应矛盾。 |
| DY-07 | Must | 和故事 / RPG / 记忆同分支作用域。 |
| DY-08 | Should | 已读不回可记进故事，不发推送。 |
| DY-09 | Should | 角色互评，遵守知情范围。 |
| DY-10 | Should | 用户发帖可选可见范围和是否写入世界。 |
| DY-11 | Should | 等待帖：点名提问，等评 / 开聊 / 不理。 |
| DY-12 | Should | 打开动态时补生成有条数上限（每角色每世界日 0–1）。 |
| DY-13 | Should | 点帖跳回来源章节或第一夜事件。 |
| DY-14 | Later | 配图复用已有生图；不自动每帖出图。 |

### 10.5 非目标

- 不做关注、转发、热搜、真社交、未读红点催登。
- 不做点赞升级、连签、稀有帖。
- 不做独立水文流水线。
- 不做立绘嘴型 / 语音同步。

### 10.6 验收

- 默认安装聊 30 轮，主路径零「动态」入口。
- 开启后若无章节和日更，动态为空。
- 同一事件可以出现「公开说法 ≠ 章节事实」；实情能看，拆穿后角色不能否认章节里已有的事实。
- 从帖开聊，角色第一句能对上那条帖，而不是当无头聊天。
- 完成「第一夜」安顿下来后，最多出现与该事件相关的派生帖，且能点回事件或章节。
- 导演台让 A 回避私聊后，A 不能在评论里引用那场私聊对白。
- 关掉后停止生成；已有帖可清理。

## 11. P2 需求包：桌上玩具

## 13. 跨切需求

### 13.1 上下文与预算

故事记忆、RPG 状态摘要、舞台提示、资料引用，全部经现有 `ChatGenerationPipeline` 注册，不得改 `chat_providers.dart` 主流程。

默认预算（可调，但必须有默认）：

| 来源 | 默认 |
| --- | --- |
| 记忆 | 小预算，只取最相关若干条 |
| RPG 状态 | 短摘要 + 允许的行动 |
| 舞台 | 在场名单 + 本轮提示 |
| 资料 | 少而可追溯的片段 |
| 动态 | 默认不注入聊天。仅当用户发帖勾选「写入世界」，或角色在聊天中引用某帖时，带一条短引用 |

超预算时确定性裁剪，并在诊断面板显示谁被裁了。失败的贡献者不得阻断普通聊天。

### 13.2 分支与数据隔离

凡写入「世界」的数据（记忆、章节、高光、RPG 状态、资料绑定、日更摘要、动态帖）必须带分支/会话作用域。Swipe 备选回复不写正式世界，除非用户选中该备选。

### 13.3 本地与费用

- 能本地做的用 SQLite / FTS / 规则引擎。
- 会调用当前 LLM 的动作（分章、记忆提取、日更摘要）必须标明「复用当前 AI」，并允许改为纯手动。
- 不新增强制 API Key。
- 外部服务保持 BYOK。

### 13.4 性能与存储

- 1000 条记忆检索保持现有基线。
- 故事页打开不超过短等待；超长会话用分页/按章加载。
- 存储统计进入现有清理工具：故事附件、场景快照、资料、音频可扫描删除。

### 13.5 无障碍与文案

- 面向用户的词：故事、章节、高光、场景、舞台、资料、世界、骰子、动态。
- 不对新手说：FTS、contributor、patch、schema、embedding、token budget。
- 这些词可以留在「全部」设置和诊断里。

### 13.6 测试

每个 P0/P1 包必须覆盖：

1. 全新用户主路径（功能关闭或未触发）。
2. 默认开启后的最小快乐路径。
3. 关闭功能后的提示词回归。
4. 书签分叉隔离。
5. 无 LLM / 无权限 / 离线。
