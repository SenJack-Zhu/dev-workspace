# NativeTavern 本地优先并行开发计划

更新日期：2026-08-07

产品方向补充（待审核，尚未改本路线任务）：见 `docs/playable-world-requirements.md`。通过后只补默认体验与叙事层缺口，不推翻下方任务 ID。


## 1. 产品边界

NativeTavern 是本地 App，不运营中转 API、语音、图片、向量或 MCP 云服务。

1. 能复用当前 LLM 配置的功能直接复用，不要求重复填写 API Key。
2. 能在本地完成的能力优先使用 SQLite、FTS、规则引擎和系统 API。
3. 系统 TTS/STT 只要求操作系统权限与设备能力；系统实现是否联网必须向用户说明。
4. 云端或自托管 TTS/STT、图片、Embedding、MCP 均为可选 BYOK。
5. 每项能力在 UI 中统一标记为：内置、复用当前 AI、需要权限、需要下载、外部服务。

## 2. 本轮不开发的范围

以下方向已从路线中删除，不占用后续排期：

- 角色工坊与角色卡体检。
- NativeTavern 扩展系统或玩法包市场。
- 内置本地 LLM、Embedding、STT、TTS 模型下载与管理。

这里不影响用户继续导入角色卡、Live2D 模型或使用已有的外部/局域网服务。

## 3. 并行开发规则

为减少多分支合并冲突，所有任务遵守以下边界：

1. `J02` 是唯一负责重构聊天上下文与生成主流程的任务。其他功能通过注册接口接入，不直接同时修改 `chat_providers.dart` 的核心流程。
2. `J03` 是同一开发批次内唯一修改 Drift 表清单、`schemaVersion` 和迁移主逻辑的任务。各业务任务先提交数据契约，再由 `J03` 集中落表。
3. `J08` 集中处理路由、设置首页入口、完整多语言翻译和生成文件。业务任务只实现独立 Screen/Widget。
4. Provider 协议适配放在独立文件中；OpenAI、Claude、Gemini 适配任务不互相修改文件。
5. 每个任务必须包含单元测试；跨功能集成测试由对应的 Integration 任务负责。

任务规模：`S` 约 1-2 天，`M` 约 3-5 天，`L` 约 6-10 天。规模仅用于拆分，不是发布日期承诺。

## 11. 推荐并行批次

### Batch 1：先固定契约与公共边界

可并行：

- Lane 1：`A01` + `A02`。
- Lane 2：`B01`。
- Lane 3：`C01`。
- Lane 4：`F01` + `J07`。

随后合并 `B01/C01/F01`，由 `J03` 单独完成统一数据库迁移。

### Batch 2：各业务核心并行

可并行：

- Lane 1：`A03` + `A04`。
- Lane 2：`B02` + `B04`。
- Lane 3：`C02` + `C04`。
- Lane 4：`F02` + `F03`。

`J02` 应在需要接入聊天主流程之前独立完成，不与 B07/C05/F07/G09 并行修改核心聊天文件。

### Batch 3：UI、检索与语音并行

可并行：

- Lane 1：`B03` + `B05` + `B06`。
- Lane 2：`C03` + `C06`。
- Lane 3：`F04` + `F05` + `F06`。
- Lane 4：`E01` + `E02`。

### Batch 4：集成任务

`B07`、`C05`、`F07` 分别通过 `J02` 的扩展点接入；三者可在独立文件中并行开发，但最终上下文顺序和 Token 预算由一个集成任务统一验收。

同时可以启动 `G01`。完成后 `G02/G03/G04` 可三路并行，`G05/G06/G07` 可进入下一批。

### Batch 5：沉浸、MCP 与收尾

可并行：

- Lane 1：`E03` + `E04` + `E05`。
- Lane 2：`G05` + `G06`。
- Lane 3：`G07` + `G08`。
- Lane 4：`B08` + `F08` + `J05`。

最后串行完成 `G09`、`J08`，再并行执行各模块集成测试，最终由 `J09` 做设备与发布门禁。
